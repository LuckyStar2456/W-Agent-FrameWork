# Harness 开发框架核心基线

[English](./harness-core.en.md) | 简体中文

> 版本说明：本页新框架核心纳入 2.1.0。下方“未发布”与候选 2.0.0 元数据属于发布前阶段记录，不代表 2.1.0 包状态。参见[2.1.0 发布说明](./releases/2.1.0.md)；上传状态以 [PyPI](https://pypi.org/project/wagent-framework/2.1.0/) 为准。

W-Agent 的目标是借鉴 Spring IoC、DI、AOP 和生命周期思想的 Python Harness 开发框架，不是固定 Harness。开发者通过注解、显式 Python 或配置装配自己的执行体系。官方 ReAct、Workflow、模型模板与 CLI/TUI 都是可选实现。

本基线于 2026-10-01 固定，作为 M0–M5 的实现与验收依据。2.0.0 的发布记录和旧 B01–B12 清单仍有效，但不能证明本基线已完成。新增能力必须分别标记源码实现、实际验证和发布状态；下文的目标接口不是已发布 API 承诺。

## 当前断点与复用决定

| 当前源码 | 已有职责 | 本次决定 |
|---|---|---|
| `container/bean_factory.py` | 定义注册、构造器及部分 setter 注入、组件扫描、生命周期 | 保留旧调用语义；以显式适配器接入新装配，不直接复用私有实例缓存或重复登记销毁方法 |
| `core/decorators.py` | 组件与生命周期元数据；Retry/CircuitBreaker 方法包装 | 保留既有名称；声明编译到统一定义，缺失的配置注入必须补齐，不能仅保留标记 |
| `kernel/registry.py` | 按能力、名称、版本和路径查找贡献；可撤销注册 | 继续作为能力索引，不负责构造或销毁对象；不得成为第二个对象容器 |
| `kernel/plugins.py` | 插件依赖、加载卸载、效果清理 | 管理插件边界，通过显式桥接贡献组件定义或借用对象；每项资源只设一个销毁所有者 |
| `kernel/scope.py` | 层级路径和可见性 | 复用路径语义；补生命周期作用域，不能将路径标签当作已实现的隔离或对象生命周期 |
| `aop/proxy_factory.py` 与 `kernel/events.py` | 方法代理、事件与 pipeline | 复用有用契约，增加容器管理的切面匹配和织入；通知事件不等于执行拦截 |
| `local_runtime.py` | 手动构造路由、执行器和 ReAct | 迁移为默认装配适配器；保留原函数作为兼容入口，不继续作为另一套核心 |

判断来自源码读取，不是本轮运行时验收。现有组件链路测试证明仓库有相应用例，不代表新架构已经通过。

## 职责与所有权

```text
注解扫描 / 显式 Python / 配置选择
                   ↓
       组件定义 → 装配校验与依赖图
                   ↓
     ApplicationContext → 作用域实例与生命周期
           ↕                     ↓
     插件桥接与能力索引      默认或用户 Harness
                                  ↑
                    Python / CLI / TUI 公共入口
```

`ApplicationContext` 是目标公开入口，负责装配、启动、解析、作用域创建和关闭，不拥有固定 Agent 算法。注册表解析能力；对象容器解析依赖。两者共享明确的身份映射，不使用两个同名缓存各自创建对象。

| 资源来源 | 生命周期所有者 | 关闭规则 |
|---|---|---|
| 组件工厂创建 | 创建它的容器作用域 | 初始化前登记清理责任；失败或关闭时依赖逆序释放一次 |
| 宿主传入的实例 | 宿主 | 容器只借用，不自动初始化、关闭或探测 `close` 方法 |
| 插件自行创建并登记效果的实例 | 插件 | 容器只借用；先停用依赖消费者，再交插件释放 |
| 插件贡献的组件工厂 | 工厂实例所在容器作用域 | 插件不能同时登记实例释放；卸载先关闭其消费者和实例，再撤销定义与能力引用 |
| 能力注册句柄 | 创建句柄的装配/插件作用域 | 撤销只影响可发现性，不隐含关闭 Provider |

不接受隐式所有权转移。将旧 BeanFactory 作为桥接资源时，要么宿主管理，要么由一个容器清理钩子整体管理；不得逐对象再登记同一销毁行为。

## 固定装配契约

1. 三种入口最终生成同一种组件定义；配置只能选择宿主允许的定义，不能靠字符串任意导入 Python。加载模块必须是独立的显式行为。
2. 定义包含名称、工厂、参数/依赖引用、生命周期作用域及可选初始化/清理行为。借用实例使用独立定义，避免默认获得清理权。不要求用户对象继承框架基类。
3. 启动前检查重复定义、缺失依赖、歧义、依赖环、参数冲突及作用域捕获。报错给出组件路径，不输出配置值、凭据或提示词。
4. 默认不覆盖同名定义。选择另一实现必须在装配前明确表达；启动后的定义不可变。热替换活跃对象不纳入本次目标。
5. 生命周期层级复用 Application → Workspace → Session → Agent → Run → Step；自定义层级须明确声明顺序。长生命周期对象不能直接捕获更短生命周期实例。延迟 provider/工厂引用需独立契约，不能绕过检查。
6. 启动依赖优先，关闭消费者优先。初始化失败仍清理已经创建的对象；工厂返回前的内部资源由工厂负责回滚。工厂需返回实例，不能悄悄后台启动未登记任务。
7. 取消不得截断已登记清理；并发关闭共享一次清理过程，单项失败不能阻止其他资源释放。保留主异常与清理错误，禁止静默吞掉取消。
8. 应用关闭前停止接收新运行，再等待或按显式策略取消它拥有的运行/流，关闭子作用域与组件，最后关闭依赖仍需要的插件。默认不猜测业务运行任务的所有权。

## 注解与切面契约

保留 `@AgentComponent`、`@ServiceComponent`、`@ToolComponent`、`@RepositoryComponent`、`@ControllerComponent`、`@PostConstruct` 和 `@PreDestroy` 的既有路径。M2 已实现它们到同一装配定义的编译，并接入 `@Configuration`/`@Bean`、限定注入、`Value` 配置绑定和显式模块扫描；使用方式及 142 项阶段验证见[注解开发](./annotation-development.md)。

M3 的切点基于组件身份、公开方法和可选标签；不能依赖内置 ReAct 私有方法名。定义 Before/Around/After/错误与最终清理语义、稳定排序和可诊断的匹配结果。默认 continuation 只推进一次，重试必须使用独立、显式且受安全策略约束的机制。

同步、协程及异步流分别定义调用语义。异步流的资源寿命覆盖消费过程，不能在返回迭代器时提前结束切面；完成、异常、取消、主动 `aclose()` 和作用域关闭均进入清理路径。事件只做通知，不能隐式替代调用授权、拦截或预算准入。

普通 Python 模块与切面是受信宿主代码，不宣称提供安全隔离。不可信代码继续使用沙箱；业务权限、逐调用批准和强制预算边界不能仅由可删除切面承载。

## 兼容与迁移

- Python 3.11+，继续使用 `w_agent`，不创建 `w_agent.v2`。
- 保留必要的 `BaseAgent.arun()`、既有装饰器与 BeanFactory 使用方式。旧容器不会自动升级到新语义，适配边界必须明确。
- 现有 Provider/HTTP 映射、路由、工具、MCP、ReAct、Workflow、知识、Session、预算、分享与沙箱逐步接入统一装配，不重写其业务协议。
- 用户的新模型参数或消息类型通过自定义协议、能力与适配器承载，不强制转换成 OpenAI 请求。
- ReAct/Workflow 是默认组件。CLI/TUI 加载相同的公开装配与执行入口；界面可以只展示其支持的内容，但不能另建不同的执行语义。
- 无租户、托管账户或云计费平台；Docker 和明确授权的非隔离本地执行边界不变。
