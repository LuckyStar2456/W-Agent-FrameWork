# 2.0.0a9 release notes

English | [简体中文](./2.0.0a9.md)

Release date: 2026-09-28. Distribution `wagent-framework`, import `w_agent`, Python 3.11+. This release collects post-a8 shared budgets, durable accounting and CLI/TUI wiring. Features remain Experimental; the framework is not complete.

## Additions since a8

- Replaceable shared-budget protocols and memory/SQLite controllers: input, output, total-token and optional monetary limits, atomic pre-call reservations and actual-Usage settlement. Missing Usage or interruptions retain unknown allowance without automatic retries.
- Replaceable Provider wrapper with host-supplied reliable input/output/price bounds. Summary and main Agents can explicitly share one pool. Character estimates are not promoted to reliable upper bounds.
- Explicit SQLite initialization, configuration binding, transactional admission, durable tickets and reopening. Hosts may reconcile pending/unknown calls only after confirming inactivity and independent evidence, retaining idempotent immutable receipts.
- Named Runtime/Provider bindings and original-client lifecycle management. JSON references names only, never code or authority; missing bindings fail closed.
- CLI run, run-resume, evaluate, provider-probe and matching TUI forms expose independently authorized factories and pool snapshots. One pool spans each evaluation batch. Safe probes do not generate; active probes reserve requests capped at 8 output tokens. Saved evaluation-report schemas remain unchanged.
- Replaceable `SQLiteSessionSummaryObserver` persists prompt-free summary-Run usage reports, with explicit initialization, idempotent updates, reopening and explicit aggregation.
- Both language editions of README, API, Runtime, TUI, evaluation, budget/accounting guides and roadmap are updated. Large-character/emoticon TUI branding, the 1.x foundation and previous alpha functionality remain.

## Usage and boundaries

```sh
python -m pip install --pre "wagent-framework[models,tui]==2.0.0a9"
wagent --version
wagent tui
```

- Shared budgets default off. `shared_budget.binding` must match a host controller/meter. CLI additionally requires `--budget-entry module:factory --confirm-budget-code`; TUI requires per-attempt `LOAD BUDGET`. Model, tool and approval permissions remain separate. Factories execute trusted unsandboxed host code.
- Only wrapped routes are covered, not hidden retries or unwrapped tools/embedding/retrieval services. Native-cursor metering remains unsupported and the configuration combination is rejected before assembly. Hosts own reliable Provider-specific upper bounds; unknown vendor billing behavior cannot be guaranteed.
- Pool snapshots are not exclusive Run/evaluation usage and must not be added twice. Snapshot failures neither alter results nor replay models. Summary reports, main Runs and shared tickets remain separate ledgers.
- SQLite expects trusted local files, not tenant isolation, execution leases, signed ledgers or cross-file transactions. Cancellation is not a refund; worker commits may finish after cancellation, requiring reopened inspection. There is no automatic cleanup or vendor-bill reconciliation.
- a9 first ships the shared-budget format: schema/configuration version 1, ordinary tickets version 1, reconciled tickets version 2. Do not mix old worktree implementations lacking version-2 support.

## Progress and remaining modules

Budgeting and durable accounting now connect to existing run, resume, evaluation and probe entry points. Remaining: unified durable preparation/main-Run accounting and automatic aggregation; concrete external retrieval backends; additional Provider media output and native-cursor/cross-process continuation; dedicated TUI media rendering; advanced MCP; sandbox network policies, legacy adapters and real-environment acceptance; online plugin discovery/locking/upgrades; final end-to-end Agent-development acceptance.

Multi-agent, deep/distributed Workflow, cross-Store atomic transactions and signed trust networks remain reserved designs. See the [roadmap](../roadmap.en.md).
