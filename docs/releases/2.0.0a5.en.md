# 2.0.0a5 release notes

English | [简体中文](./2.0.0a5.md)

Release date: 2026-09-27. Distribution: `wagent-framework`; import: `w_agent`; Python 3.11+. This incremental alpha focuses on local pause and approval continuation. Framework development is not complete.

## Changes since a4

- `SQLiteWorkflowPauseController` persists local cross-process pause requests by exact run ID. CLI commands request, inspect, clear, and explicitly observe them during recovery. Read failures fail closed; clearing does not resume, and requesting does not acknowledge a pause.
- `AnyWorkflowPauseSource` provides ordered read-only OR composition. The TUI can explicitly combine its operation-local controller with SQLite, leaving external durable requests intact on cleanup.
- `WorkflowNodeResult(suspend=True, pause=True)` saves state without completing the current node and emits `node-suspended`. Existing completed-node pause behavior remains compatible.
- `approval_agent_workflow_node()` and optional `ResumableAgentLoop` retain exact child-run/call references while an embedded Agent awaits approval. Fresh explicit authority continues that child after definition, scope, and checkpoint validation.
- `review_workflow_approvals()`, CLI `checkpoint workflow-approvals`, and TUI read-only review expose parent/child identifiers and match status, not messages or tool arguments. They import no code and grant no authority.
- `WorkflowApprovalGrants` is explicitly injected, host-owned, one-shot in-memory authority bound to reference and scope. Grants expire after 300 seconds by default and can be revoked or cleared. Only the current call is consumed, never subsequent calls implicitly.
- Fixed missing type-name imports in legacy AOP and dynamic configuration; updated bilingual API, Workflow, TUI, roadmap, and entry documentation.

## Compatibility and limitations

- Existing nodes, pause behavior, and public WorkflowStore contracts remain unchanged. Older event readers may reject the new `node-suspended` enum value; upgrade readers first.
- SQLite requests require a trusted local filesystem. They provide neither execution locks, process-liveness evidence, nor multi-primary recovery.
- Hosts explicitly assemble the same Agent store and authority callback. CLI/TUI provide approval-link review only; full interactive approve-and-resume wiring remains planned.
- Parent and child stores have no atomic transaction. Uncertain execution retains `RESUMING` and must not replay side effects automatically. One-shot grants do not guarantee exactly-once execution after a crash.

## Installation

```sh
python -m pip install --pre "wagent-framework[models,tui]==2.0.0a5"
wagent --version
wagent tui
```
