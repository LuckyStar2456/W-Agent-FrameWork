# 2.0.0a6 release notes

English | [简体中文](./2.0.0a6.md)

Version date: 2026-09-27. Distribution: `wagent-framework`; import: `w_agent`; Python 3.11+. This release focuses on approval recovery and event-display foundations. Additions are `Experimental`; framework development is not complete.

## Changes since a5

- CLI/TUI approve-and-resume for an Agent inside Workflow: explicit async factory assembly, exact parent/child identities, separate code/approval/execution confirmations, checkpoint rechecks before/after assembly, and operation-local grant cleanup on exit/cancellation.
- `ToolContinuation`, optional resume protocol and ReAct schema 2 checkpoints: unfinished tools retain tickets and continue through separate handlers. Ticket-free checkpoints retain schema 1; neither initial tools nor preceding model requests restart automatically.
- `resumable_workflow_tool()`: reference-first Agent-to-Workflow suspension/continuation with parent/child linkage. Existing `workflow_start_tool()` / `workflow_resume_tool()` semantics are unchanged.
- Two-layer approval service, CLI and TUI Approval chains page: read-only linkage, explicit row selection, independent parent/child permissions and four confirmations; execution proceeds only through parent Agent recovery.
- `RunEventAccumulator`, replaceable `RunEventReducer` and versioned `RunReplaySnapshot`: reconstruct recorded text, tool-status and media views across pages. Defaults hide content, snapshots are bounded, and failed pages leave input snapshots unchanged. No model/tool execution or execution-checkpoint replacement.
- TUI regression now checks all 11 page identities, including approval chains. Large-character branding, emoticons and narrow-window fallback remain available.
- Synchronized bilingual README, guides, API, Workflow, tools, event replay and roadmap.

## Compatibility and boundaries

- New readers support schemas 1/2. Older releases may reject schema 2 checkpoints carrying continuation tickets; upgrade recovery readers first.
- Factories are explicitly authorized trusted local Python, not sandboxes. They must faithfully assemble the same stores and authority callbacks. Query/snapshot matches do not grant authority.
- Trusted local storage and single ownership are required. Cross-store atomic commits, distributed locks, arbitrarily deep recursive approval and exactly-once crash recovery are not implemented. Uncertain execution retains `RESUMING`; never replay side effects automatically.
- Display snapshots are neither execution recovery points nor proofs of log authenticity. Default CLI/TUI retain safe event views; rich accumulated-content UI remains pending.
- `TOOL_COMPLETED` does not yet record result bodies. Replay cannot infer unrecorded content.

## Installation

```sh
python -m pip install --pre "wagent-framework[models,tui]==2.0.0a6"
wagent --version
wagent tui
```

## Remaining modules

Optional tool-result body recording, rich Session projection and replay UI; other vendors' multimodal output and native-cursor adapters/cross-process continuation; advanced MCP; sandbox network policy, legacy-backend adapters and broader environment acceptance; online plugin discovery/locking/upgrades; final complete Agent-development-chain acceptance. Multi-agent support, nested/distributed workflows, cross-store atomic transactions and signature trust networks remain reserved. See the [roadmap](../roadmap.en.md).
