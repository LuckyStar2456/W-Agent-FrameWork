# W-Agent 2.1.0

English | [简体中文](./2.1.0.md)

2.1.0 includes the Spring-inspired Harness development core accepted through M0–M5: IoC, DI, AOP and lifecycle support user-defined execution systems, with ReAct/Workflow as optional recipes. Requires Python 3.11+; the import remains `w_agent`. Check [PyPI 2.1.0](https://pypi.org/project/wagent-framework/2.1.0/) for upload status. This document describes release scope; a successful build is not proof of publication.

## New core

- `AssemblyPlan` and `ApplicationContext`: unified dependency validation, component ownership, scopes, initialization rollback, cancellation and cleanup.
- `compile_assembly`, `compile_decorated`, `compile_configured`: explicit Python, decorators and configuration share a plan; configuration selects only host-allowed definitions.
- `Configuration`/`Bean`, component scanning, typed/qualified injection, `Value` binding and lifecycle annotations.
- `Aspect`, Before/Around/After/OnError/Finally: synchronous, asynchronous and streaming advice/cleanup; plugin bridging preserves custom scope order.
- `ApplicationProject`/`ApplicationHost`: public project execution through Python/CLI/TUI; replaceable Loop, router and executor in default Runtime/Workflow recipes.
- Three bilingual tutorials and offline examples: custom Harness, annotated support and configured coding.

## Installation and development

```bash
python -m pip install "wagent-framework==2.1.0"
# Optional HTTP models and TUI
python -m pip install "wagent-framework[models,tui]==2.1.0"
```

Start with [Develop your own Harness](../harness-development.en.md) and [README](../../README_EN.md). Legacy containers, proxies and synchronous Runtime do not automatically acquire new semantics; see [migration](../migration-1x.en.md). Wheels do not distribute an `examples` package; copy examples and accompanying JSON from matching sdist/source.

## Acceptance basis and release boundary

Reuse [core acceptance](../harness-acceptance.en.md): 259 related tests, static checks on 33 files, executed bilingual README quickstarts, offline wheel/sdist, isolated installation and three outside-repository examples through Python/CLI/headless TUI. This release changes only version/package description and documentation. Framework source is compared byte-for-byte against the accepted artifact, allowing only `__version__` to change from 2.0.0 to 2.1.0. No tests rerun, new installation, real-model calls or Git commit/push during publication.

Release artifacts receive source/metadata consistency checks and `twine check --strict`, followed by comparison of both PyPI artifact hashes after upload. No claim of reinstalling from PyPI. Earlier local-candidate 2.0.0 metadata was an acceptance identifier, not a republication or overwrite of PyPI 2.0.0.

## Remaining boundaries

Ordinary Python/plugins/aspects are trusted code, not a security sandbox. Per-call approval and mandatory budgets must not rely solely on removable aspects. Host does not supervise independently spawned tasks or forcibly stop uncooperative synchronous code. CLI/TUI transport supported JSON/display types only. The coding example changes memory and never executes generated code.

No full-suite regression, real-model quality/billing or all-platform verification. Existing Experimental peripheral features do not automatically become stable. Multi-agent systems, distributed Workflow, remote sandboxes, plugin marketplaces and advanced hot migration remain reserved; see the [roadmap](../roadmap.en.md).
